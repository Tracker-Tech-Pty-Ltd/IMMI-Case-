## 程式碼覆核與修正

- 遠端 SQL 驗證工具原先依 `prepare()` 順序記錄語句；目前每表交易會先準備新增語句，導致回放先新增再刪除。改為記錄 `run`／`all`／`first`／`batch` 的實際執行順序，並統一 SQL 前後空白。真實 SQLite 回放確認統計有資料、待辦世代不丟失、租約排他與每日計數不被重建清除。
- 重送回歸保留「已完成的向量處理不重複付費」斷言，故障注入調整至持久化待重算標記的實際交接點。
- 統計完整性測試同時涵蓋有保留條件的 summary 刪除、部分失敗不發布已完成世代，以及租約被取代時不寫入統計表。
- CI 收集防線測試讀取文字時統一 CRLF／LF，避免 Windows 將整份 workflow 誤判成單一 job；沒有放寬實際防線。
