# 本機案件修復：固定流程與本輪核對（2026-10-21）

本輪重點是修正反覆執行卻沒有新證據的工作方式。新的本機下載會保留已填欄位；缺漏欄位只接受能連結到本案的原文證據。覆核紀錄會記住來源與規則，相同證據再次執行會跳過；原文、案件身分、規則或參考快取改變時才重開檢查。

這不表示未公開的資料都能補出。本輪沒有發現可安全新增的法官、結果或簽證值，因此沒有為了減少數字而填入推測。

所有未確認欄位均有逐筆原因，包含：未明列本案簽證、僅歷史／法條／他人簽證、身分或候選矛盾、未明列裁決者、只有擬議或尚待作成的命令，以及原文不完整或受公開限制。11 案來源繼續保留原檔與歷次查找紀錄。本輪另查公開索引，兩個法院官方網址仍無法由網頁工具讀取，沒有取得新的完整原文。沒有重新下載未改變的失敗路徑，也沒有把論文、搜尋摘要、錯案附檔或短片段冒充全文。

## 已修正的原因

- 表格內容以儲存格及段落分隔，避免法官、日期與地點黏在一起。
- 法官須出自本案作者欄或本案認證文字；受損表格的「Sydney」與只有職稱而無姓名的內容會被攔下。
- 結果須出自正式裁決區塊；日期、法律原則、擬議命令、未完句及尚待進一步聆訊的處分會保留待確認。
- 簽證須有本案審查關係；不再取全文第一個簽證名稱，也不從計畫名稱、舊簽證或法條列舉推斷類別。
- 搜尋端排除沒有實際移民內容的 Visa International 信用卡訴訟，避免相同誤分類再次累積。
- 重新下載時，只補空值，保留既有欄位。
- Jev 快取按原文內容、案號與網址綁定。模型答案只作參考；高信心分數不能授權寫入。
- 本機寫入共用同一個程序鎖；支援 Windows，保留原本 POSIX 鎖。三份資料的寫入有備份、明確核准清單、中斷紀錄及恢復入口。

原來供 Python／Worker 對照用的 `MetadataExtractor` 與 Worker 規則沒有改寫。新的保守規則接在兩個本機下載器上；沒有部署雲端或改動雲端設定。

## 後續操作

統一入口是 `scripts/repair_case_fields.py`。用專案的 Python 執行：

```text
python scripts/repair_case_fields.py review --output downloaded_cases/updates/case-field-review
```

既有覆核狀態與 Jev 快取位置會從本機紀錄接續；不用每次重建清單或再次付費。這是可重複執行的檢查入口，沒有另外設定排程，也不會自行發出網路或付費請求。新下載案件會直接採用修正後的擷取規則。

`review` 只整理狀態與有證據的候選。`apply --approvals <核對清單>` 只寫入獨立核對過的值，並再次檢查來源是否改變、三份資料是否衝突、原有欄位是否非空。中斷後使用 `recover`；若有無關資料被其他程序改動，會停止自動恢復，避免用舊備份覆蓋新資料。

本輪已把舊清單與原文追查紀錄匯入持續覆核紀錄。等待新證據的項目不是尚未處理的工作；有新原文或新來源後才值得重查。
