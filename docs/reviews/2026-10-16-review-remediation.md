## 交叉複審追加修正

- 全文替換時，缺省的年份不能變成空值；新增實際 API 路徑回歸。
- 新來源上傳後，若待清理紀錄儲存失敗，會清理尚未發布的新物件。
- 案件資料、法官／概念關聯及全文段落改為單次原子交易，避免讀到混合版本。
- 相同續期識別碼的重疊伺服器請求須視為同一次重試；過期、登出、已再次輪替或不同識別碼仍拒絕。
- 既有遠端 Supabase schema 測試改為必須明確設定 `IMMI_LIVE_SUPABASE_TESTS=1`，避免一般測試自動使用本機憑證接觸舊服務。
- 舊瀏覽器測試對照目前導覽、快捷鍵及 Radix 確認視窗更新操作契約，保留實際功能斷言。

## 再次審查

由不同代理交叉檢查 Python、前端及 Worker 修正，對具體發現建立會失敗的測試或真實 SQLite 重現，再修正並重新驗證。最後獨立覆核確認年份保留、清理紀錄失敗補償及相同登入重試的安全條件均符合預期，未發現本輪修正仍有可重現、需補修的缺陷。

登入路徑按高風險處理，補跑實際 JWT／SQLite 重疊請求及真實瀏覽器跨分頁測試。GitNexus 對動態 pytest／React 路徑有無法解析的情況；這些部分以實際來源呼叫鏈與回歸測試補查，沒有把找不到呼叫者當成沒有影響。

最後執行 `detect-changes --scope compare --base-ref main --repo IMMI-Case-`，工具列出 57 個受追蹤變更檔、20 個對應符號並回報 `critical`。其 460 個流程包含將 Python `_run_clean_phase` 對應到瀏覽器流程的明顯不合理結果，因此保留原始輸出供查核，未把圖譜當成完整影響範圍證明，也未宣稱風險已消失。實際差異、原始呼叫者、完整測試及交叉複審共同作為本輪依據；新增未追蹤檔案另行逐檔檢查。格式檢查通過，變更原始碼的常見憑證模式掃描無命中。
